# /ux-copy

> 見慣れないプレースホルダがある場合や、どのツールが連携されているか確認したい場合は、[CONNECTORS.md](../../CONNECTORS.md) を参照してください。

あらゆるインターフェースの文脈に合わせて UXコピーを執筆・レビューします。

## 使い方

```
/ux-copy $ARGUMENTS
```

## 必要な情報

- **文脈**: どの画面・フロー・機能ですか？
- **ユーザーの状態**: ユーザーは何をしようとしていますか？どんな気持ちですか？
- **トーン**: フォーマル、フレンドリー、遊び心のある、安心させる、など？
- **制約**: 文字数制限、プラットフォームのガイドラインはありますか？

## 原則

1. **明確（Clear）**: 言いたいことを正確に述べる。専門用語や曖昧さを排する。
2. **簡潔（Concise）**: 意味を完全に伝える最小限の語数で書く。
3. **一貫（Consistent）**: 同じものには、どこでも同じ用語を使う。
4. **有用（Useful）**: すべての語が、ユーザーの目標達成に役立つべき。
5. **人間らしい（Human）**: ロボットではなく、親切な人のように書く。

## コピーのパターン

### CTA（行動喚起）
- 動詞で始める: 「無料トライアルを始める」「変更を保存」「レポートをダウンロード」
- 具体的に: 「送信」ではなく「アカウントを作成」
- ラベルと結果を一致させる

### エラーメッセージ
構成: 何が起きたか + なぜか + どう直すか
- 「お支払いが拒否されました。ご利用のカードが銀行側で拒否されました。別のカードをお試しいただくか、銀行にお問い合わせください。」

### 空状態（エンプティステート）
構成: これは何か + なぜ空なのか + どう始めるか
- 「まだプロジェクトがありません。最初のプロジェクトを作成して、チームとのコラボレーションを始めましょう。」

### 確認ダイアログ
- アクションを明確に: 「本当によろしいですか？」ではなく「3件のファイルを削除しますか？」
- 結果を説明する: 「この操作は取り消せません」
- ボタンにはアクションをラベル付け: 「OK」「キャンセル」ではなく「ファイルを削除」「ファイルを残す」

### ツールチップ
- 簡潔で役に立ち、当たり前のことは書かない

### ローディング状態
- 期待値を設定し、不安を軽減する

### オンボーディング
- 段階的開示（プログレッシブ・ディスクロージャー）、一度に1つの概念だけ

## ボイスとトーン

文脈に合わせてトーンを調整します。
- **成功時**: 祝福するが、やりすぎない
- **エラー時**: 共感的で、助けになる
- **警告時**: 明確で、行動につながる
- **中立時**: 情報を伝え、簡潔に

## 出力

```markdown
## UXコピー: [文脈]

### 推奨コピー
**[要素]**: [コピー]

### 代替案
| 選択肢 | コピー | トーン | 適した場面 |
|--------|------|------|----------|
| A | [コピー] | [トーン] | [使うべき場面] |
| B | [コピー] | [トーン] | [使うべき場面] |
| C | [コピー] | [トーン] | [使うべき場面] |

### 根拠
[なぜこのコピーが機能するか — ユーザーの文脈、明確さ、行動志向]

### ローカライズに関するメモ
[翻訳者が知っておくべきこと — 避けるべき慣用句、文字数の膨張、文化的な文脈]
```

## コネクタが利用可能な場合

**~~knowledge base** が連携されている場合:
- ブランドボイスのガイドラインやコンテンツスタイルガイドを取得する
- 既存のコピーパターンや用語の標準を確認する

**~~design tool** が連携されている場合:
- Figma で画面の文脈を確認し、ユーザーフロー全体を理解する
- デザインから文字数制限やレイアウトの制約を確認する

## ヒント

1. **文脈を具体的に** — 「エラーメッセージ」より「支払い失敗時のエラーメッセージ」のほうが適切です。
2. **ブランドボイスを共有する** — 「プロフェッショナルだが温かい」といった情報があると、トーンを合わせやすくなります。
3. **ユーザーの感情状態を考慮する** — エラーメッセージには共感が必要です。成功メッセージは祝ってよいのです。
