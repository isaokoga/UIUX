# /design-critique

> 見慣れないプレースホルダがある場合や、どのツールが連携されているか確認したい場合は、[CONNECTORS.md](../../CONNECTORS.md) を参照してください。

複数の観点から構造化されたデザインフィードバックを得ます。

## 使い方

```
/design-critique $ARGUMENTS
```

次のデザインをレビューします: @$1

Figma の URL が指定された場合は、Figma からデザインを取得します。ファイルが参照された場合は、それを読み込みます。それ以外の場合は、ユーザーにデザインの説明または共有を求めます。

## 必要な情報

- **デザイン**: Figma の URL、スクリーンショット、または詳しい説明
- **文脈**: これは何か？誰のためか？どの段階か（探索、精緻化、最終）？
- **フォーカス**（任意）: 「モバイルに注目して」「オンボーディングフローに注目して」など

## クリティークのフレームワーク

### 1. 第一印象（2秒）
- 最初に目を引くのは何か？それは正しいか？
- 感情的な反応はどうか？
- 目的はすぐに伝わるか？

### 2. ユーザビリティ
- ユーザーは目標を達成できるか？
- ナビゲーションは直感的か？
- 操作可能な要素は明白か？
- 不要なステップはないか？

### 3. 視覚的階層
- 明確な読み順があるか？
- 適切な要素が強調されているか？
- 余白は効果的に使われているか？
- タイポグラフィは適切な階層を生んでいるか？

### 4. 一貫性
- デザインシステムに従っているか？
- スペーシング、色、タイポグラフィは一貫しているか？
- 類似した要素は、類似した挙動をするか？

### 5. アクセシビリティ
- カラーコントラスト比
- タッチターゲットのサイズ
- テキストの可読性
- 画像の代替テキスト

## フィードバックの伝え方

- **具体的に**: 「レイアウトが分かりにくい」ではなく「CTAがナビゲーションと競合している」
- **理由を説明する**: フィードバックをデザイン原則やユーザーニーズに結びつける
- **代替案を提案する**: 問題を指摘するだけでなく、解決策を提示する
- **うまくいっている点も認める**: 良いフィードバックには肯定的な観察も含まれる
- **段階に合わせる**: 初期の探索と最終仕上げでは、フィードバックの内容を変える

## 出力

```markdown
## デザインクリティーク: [デザイン名]

### 全体的な印象
[1〜2文の第一印象 — うまくいっている点、最大の改善機会]

### ユーザビリティ
| 発見事項 | 深刻度 | 推奨事項 |
|---------|----------|----------------|
| [問題] | 🔴 重大 / 🟡 中程度 / 🟢 軽微 | [対処] |

### 視覚的階層
- **最初に目を引くもの**: [要素] — [これは正しいか？]
- **読み流れ**: [視線はレイアウトをどう移動するか？]
- **強調**: [適切なものが強調されているか？]

### 一貫性
| 要素 | 問題 | 推奨事項 |
|---------|-------|----------------|
| [タイポグラフィ/スペーシング/色] | [不整合] | [対処] |

### アクセシビリティ
- **カラーコントラスト**: [主要テキストの合否]
- **タッチターゲット**: [十分なサイズか？]
- **テキストの可読性**: [フォントサイズ、行間]

### うまくいっている点
- [肯定的な観察 1]
- [肯定的な観察 2]

### 優先推奨事項
1. **[最もインパクトの大きい変更]** — [理由と方法]
2. **[第2の優先事項]** — [理由と方法]
3. **[第3の優先事項]** — [理由と方法]
```

## コネクタが利用可能な場合

**~~design tool** が連携されている場合:
- Figma から直接デザインを取得し、コンポーネント、トークン、レイヤーを検査する
- 既存のデザインシステムと照合して一貫性を確認する

**~~user feedback** が連携されている場合:
- デザイン上の判断を、最近のユーザーフィードバックやサポートチケットと相互参照する

## ヒント

1. **文脈を共有する** — 「これはB2B SaaSのチェックアウトフローです」と伝えると、関連性の高いフィードバックができます。
2. **段階を指定する** — 初期の探索と最終仕上げでは、フィードバックの内容が異なります。
3. **フォーカスを指示する** — 「ナビゲーションだけ見て」と指定すると、1つの領域をより深く見られます。
