# /accessibility-review

> 見慣れないプレースホルダがある場合や、どのツールが連携されているか確認したい場合は、[CONNECTORS.md](../../CONNECTORS.md) を参照してください。

デザインまたはページを WCAG 2.1 AA 準拠の観点で監査します。

## 使い方

```
/accessibility-review $ARGUMENTS
```

次の対象のアクセシビリティを監査します: @$1

## WCAG 2.1 AA クイックリファレンス

### 知覚可能（Perceivable）
- **1.1.1** 非テキストコンテンツに代替テキストがある
- **1.3.1** 情報と構造が意味的（セマンティック）に伝えられている
- **1.4.3** コントラスト比が 4.5:1 以上（通常テキスト）、3:1 以上（大きいテキスト）
- **1.4.11** 非テキストのコントラストが 3:1 以上（UIコンポーネント、グラフィック）

### 操作可能（Operable）
- **2.1.1** すべての機能がキーボードで利用できる
- **2.4.3** 論理的なフォーカス順序
- **2.4.7** フォーカスインジケータが視認できる
- **2.5.5** タッチターゲットが 44×44 CSSピクセル以上

### 理解可能（Understandable）
- **3.2.1** フォーカス時に予測可能（予期しない変化が起きない）
- **3.3.1** エラーの特定（エラー内容を説明する）
- **3.3.2** 入力項目にラベルまたは説明がある

### 堅牢（Robust）
- **4.1.2** すべてのUIコンポーネントに名前・ロール・値がある

## よくある問題

1. カラーコントラスト不足
2. フォームラベルの欠如
3. 操作可能な要素にキーボードでアクセスできない
4. 意味のある画像に代替テキストがない
5. モーダル内のフォーカストラップ
6. ARIA ランドマークの欠如
7. コントロールのない自動再生メディア
8. 延長オプションのない制限時間

## テストのアプローチ

1. 自動スキャン（問題の約30%を検出）
2. キーボードのみでのナビゲーション
3. スクリーンリーダーでのテスト（VoiceOver、NVDA）
4. カラーコントラストの検証
5. 200% までズーム — レイアウトは崩れないか？

## コネクタが利用可能な場合

**~~design tool** が連携されている場合:
- Figma から直接、色の値、フォントサイズ、タッチターゲットを検査する
- デザイン仕様上でコンポーネントの ARIA ロールやキーボード挙動を確認する

**~~project tracker** が連携されている場合:
- 各アクセシビリティ発見事項について、深刻度と WCAG 達成基準を付けてチケットを作成する
- 発見事項を既存のアクセシビリティ是正エピックに紐付ける

## ヒント

1. **コントラストとキーボードから始める** — 最も一般的でインパクトの大きい問題を捕捉できます。
2. **実際の支援技術でテストする** — この監査は良い出発点ですが、VoiceOver/NVDA での手動テストは、私（Claude）が検出できないものを捕捉します。
3. **インパクトで優先順位を付ける** — ユーザーを妨げる問題をまず直し、磨き込みは後回しにしましょう。
