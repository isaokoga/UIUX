# /design-handoff

> 見慣れないプレースホルダがある場合や、どのツールが連携されているか確認したい場合は、[CONNECTORS.md](../../CONNECTORS.md) を参照してください。

デザインから包括的な開発者向けハンドオフドキュメントを生成します。

## 使い方

```
/design-handoff $ARGUMENTS
```

次のデザインのハンドオフ仕様書を生成します: @$1

Figma の URL が指定された場合は、Figma からデザインを取得します。それ以外の場合は、提供された説明やスクリーンショットをもとに作業します。

## 含めるべき内容

### ビジュアル仕様
- 正確な寸法（パディング、マージン、幅）
- デザイントークンの参照（色、タイポグラフィ、スペーシング）
- レスポンシブのブレークポイントと挙動
- コンポーネントのバリアントと状態

### インタラクション仕様
- クリック/タップ時の挙動
- ホバー状態
- トランジションとアニメーション（長さ、イージング）
- ジェスチャー対応（スワイプ、ピンチ、長押し）

### コンテンツ仕様
- 文字数制限
- 省略（トランケーション）の挙動
- 空状態
- ローディング状態
- エラー状態

### エッジケース
- 最小／最大のコンテンツ量
- 国際化テキスト（より長い文字列）
- 低速な通信環境
- データの欠損

### アクセシビリティ
- フォーカス順序
- ARIA ラベルとロール
- キーボード操作
- スクリーンリーダーの読み上げ

## 原則

1. **推測させない** — 指定がなければ、開発者は推測します。すべてを明記しましょう。
2. **値ではなくトークンを使う** — `16px` ではなく `spacing-md` を参照しましょう。
3. **すべての状態を示す** — デフォルト、ホバー、アクティブ、無効、ローディング、エラー、空。
4. **理由（why）を説明する** — 「ユーザーは主に片手で操作するため、モバイルではこれを折りたたむ」のように書くと、開発者が適切な判断を下せます。

## コネクタが利用可能な場合

**~~design tool** が連携されている場合:
- Figma から正確な寸法、トークン、コンポーネント仕様を取得する
- アセットを書き出し、完全な仕様書を生成する

**~~project tracker** が連携されている場合:
- ハンドオフを実装チケットに紐付ける
- 仕様書の各セクションごとにサブタスクを作成する

## ヒント

1. **Figma のリンクを共有する** — 正確な寸法、トークン、コンポーネント情報を取得できます。
2. **エッジケースに言及する** — 「100件あったらどうなる？」といった問いが、境界条件の仕様化に役立ちます。
3. **技術スタックを指定する** — 「React + Tailwind を使っている」と伝えると、関連性の高い実装メモを提供できます。
