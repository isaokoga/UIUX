# /research-synthesis

> 見慣れないプレースホルダがある場合や、どのツールが連携されているか確認したい場合は、[CONNECTORS.md](../../CONNECTORS.md) を参照してください。

ユーザーリサーチのデータを実行可能なインサイトへと統合します。リサーチ手法、インタビューガイド、分析フレームワークについては **user-research** スキルを参照してください。

## 使い方

```
/research-synthesis $ARGUMENTS
```

## 受け付けられるもの

- インタビューの文字起こしやメモ
- アンケート結果（CSV、貼り付けたデータ）
- ユーザビリティテストの録画やメモ
- サポートチケットやフィードバック
- NPS/CSAT の回答
- アプリストアのレビュー

### エグゼクティブサマリー
[主要な発見事項を3〜4文で概観]

## コネクタが利用可能な場合

**~~user feedback** が連携されている場合:
- サポートチケット、機能リクエスト、NPS回答を取得し、リサーチデータを補完する
- テーマを実際のユーザーの不満やリクエストと相互参照する

**~~product analytics** が連携されている場合:
- 定性的な発見を利用データや行動指標で裏付ける
- 特定されたペインポイントのインパクトを定量化する

**~~knowledge base** が連携されている場合:
- 過去のリサーチ調査や発見を検索し、比較対象とする
- 統合結果をリサーチリポジトリに公開する

## ヒント

1. **生の発言を含める** — 参加者の発言をそのまま引用すると、インサイトに信頼性と記憶への残りやすさが生まれます。
2. **観察と解釈を分ける** — 「8人中5人が誤ったボタンをクリックした」は観察です。「ボタンの配置が分かりにくい」は解釈です。
3. **可能な限り定量化する** — 「ほとんどのユーザー」は曖昧です。「10人中7人」は具体的です。
